# J&A pipeline: operator guide

For whoever runs this next. You don't need to be a developer for most of it, but you will need to be comfortable with GitHub's Settings pages.

## What it does

Every morning it:

1. **Collects.** Reads SAM.gov's public notice files, finds Justification & Approval (J&A) notices, downloads their attachments, extracts text (scanned pages are transcribed by Claude), and publishes everything to a Hugging Face dataset.
2. **Extracts.** Has Claude read each new J&A and fill in fields (authority cited, value, vendor, redactions, people named, and so on), each with a quote that's checked against the document. These tables are labelled experimental.
3. **Emails.** Picks the few most remarkable new notices, writes them up, and sends the "WOAH! J&As" email through Buttondown at 7:00 AM ET.
4. **Publishes the archive.** Rebuilds a small public website with every email sent, plus an RSS feed.

The dataset card on Hugging Face is generated by the code, so it updates itself. Details live in the existing docs; this file doesn't repeat them:

* [README.md](README.md): sources, tables, how collection works
* [docs/field_extraction.md](docs/field_extraction.md): the extraction fields and how they were checked
* [docs/analysis_validation.md](docs/analysis_validation.md): the theme tags
* [docs/digest.md](docs/digest.md): the email, the web archive, cost, how to turn it on and off

## Where things live

| What | Where |
|---|---|
| The data (tables, original files, AI tables) | Hugging Face dataset `abigailhaddad/federal-ja-documents` |
| The code and the schedules | This GitHub repo |
| Collection state (what's been fetched) | `data/collection_state.json` in the dataset |
| Email memory (what's been sent) | `analysis/digest_state.json` in the dataset |
| Every sent email, as data | `analysis/digest_archive/*.json` in the dataset |
| Public email archive | https://woah-jas.abigailhaddad.com (Cloudflare Pages project `woah-jas`) |
| Subscribers | Buttondown, account `abigailhaddad` |
| The thing that starts the day | A Cloudflare Worker in `cron-trigger/` |
| Run history | The Actions tab |

The matching of notices to awards reads a *different* dataset, `abigailhaddad/usaspending-bulk-awards` (a Hugging Face mirror of USAspending's award files). It's public and read-only here. If it goes away or stops updating, the `usaspending_*` columns go stale. It can stay with the current owner or be re-created; see "Moving it to a new owner."

## What runs and when

| Workflow | Starts | Needs |
|---|---|---|
| **Daily J&A collection** (`daily.yml`) | The Cloudflare Worker starts it at 06:15 UTC. GitHub's own 06:15 UTC schedule is a backup and runs only if the variable `DAILY_ENABLED` is `true`. | secrets `HF_TOKEN`, `ANTHROPIC_API_KEY`; variable `ANTHROPIC_WORKSPACE_ID` |
| **Daily experimental field extraction** (`extract-daily.yml`) | After collection succeeds, if variable `EXTRACT_DAILY_ENABLED` is `true`. Can also be run by hand. | the same two secrets and the workspace variable |
| **Daily J&A digest email** (`digest.yml`) | After extraction finishes. Also after collection when extraction is off, and a fallback at 22:30 UTC. Sends only if variable `DIGEST_ENABLED` is `true`; otherwise it does a dry run and saves it as a downloadable artifact. | secrets `HF_TOKEN`, `ANTHROPIC_API_KEY`, `BUTTONDOWN_API_KEY`; the workspace variable |
| **Deploy digest web archive** (`deploy-site.yml`) | After each sent email. Can be run by hand to rebuild the site. | secrets `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`; optional variable `CLOUDFLARE_PROJECT` (default `woah-jas`) |
| **Tests** (`tests.yml`) | Every pull request and every push to `main`. | nothing |
| **Experimental J&A tagging** (`analysis.yml`) | By hand only. Theme tagging; the tables are a one-off snapshot. | `ANTHROPIC_API_KEY`; the workspace variable |
| **SAM award backfill** (`sam-awards-backfill.yml`) | By hand only. | `HF_TOKEN` |

The daily workflow, the extraction workflow and the digest each run the tests first, so a broken change stops the day's run.

**Why the Cloudflare Worker.** GitHub's own schedule fired 5 to 7 hours late every day during the week of 2026-10-19, which made the 7:00 AM email late or missing. The Worker (`cron-trigger/`) calls GitHub at 06:15 UTC on time. It needs a GitHub token (secret `GITHUB_TOKEN` on the Worker, fine-grained, Actions read and write on this one repo) and is deployed with `cd cron-trigger && npx wrangler deploy`. If it stops, the chain stops at the first link. If the GitHub token expires, it fails quietly except for a failed invocation in the Cloudflare dashboard.

## What costs money

* **Anthropic usage.** Three jobs call the API. Each has a per-run spend cap, set in the workflow: transcription of scanned pages and extraction default to $2 a run, the digest to $0.35. The digest's own 7-day backtest averaged about $0.10 a day ([docs/digest.md](docs/digest.md#cost)). I haven't added up what the daily runs have cost in practice; check the Anthropic console for the real number. A big backfill (the manual workflows) can cost much more: tagging defaults to a $40 cap.
* **GitHub Actions minutes.** Daily runs take long (collection allows up to 300 minutes). On a public repo that's free; on a private one it isn't.
* **Hugging Face, Cloudflare, Buttondown.** Whatever plan you're on. The dataset is about 11 GB of original files plus tables.

## Moving it to a new owner

Everything outward-facing is in one place: `src/federal_ja/collect/config.py`. Edit the defaults there, or set these as environment variables:

| Setting | Default today | What it controls |
|---|---|---|
| `JA_GITHUB_REPO` | `abigailhaddad/federal-ja-documents` | Links to the code, the "report a problem" link, the user-agent string |
| `JA_HF_REPO` | `abigailhaddad/federal-ja-documents` | The dataset the pipeline reads and writes |
| `JA_USASPENDING_DATASET` | `abigailhaddad/usaspending-bulk-awards` | The award mirror used for matching |
| `JA_SITE_URL` | `https://woah-jas.abigailhaddad.com` | The archive link in each email's footer |
| `JA_BUTTONDOWN_USER` | `abigailhaddad` | The subscribe link and the signup form on the site |

The workflows don't set these, so to use environment variables, add them under `env:` in each workflow. Editing the defaults in `config.py` is simpler. With the defaults left alone, the generated dataset card, emails and website are identical to what was produced before this change (checked by building each and comparing).

Places that can't read `config.py`, so you change them by hand:

1. **Repository secrets and variables** (Settings, Secrets and variables, Actions): everything in the table above. None of them transfers with the repo.
2. **`cron-trigger/wrangler.toml`**: `GITHUB_REPO` under `[vars]`. Then redeploy the Worker and give it a new `GITHUB_TOKEN`.
3. **Cloudflare Pages**: create the project (named `woah-jas`, or set the variable `CLOUDFLARE_PROJECT`), attach your domain, and set `JA_SITE_URL`.
4. **Buttondown**: your own account; set `JA_BUTTONDOWN_USER` and the API key secret.
5. **Hugging Face**: create the dataset repo and an `HF_TOKEN` that can write to it. Existing data doesn't move on its own: copy it over. I haven't tested a first run against an empty dataset, so try that on a small date range before relying on it.
6. **`README.md`, `NOTICE`, `docs/digest.md`**: the owner's name appears in links and in the `gh secret set` examples. `docs/digest_samples/` holds old sample emails with their original links; leave those.
7. **Comments in the code** mention the old site address in a few docstrings (`digest/site.py`, `digest/archive.py`, `tests/test_site_dist.py`). They're harmless.
8. **Variables to create:** `DAILY_ENABLED`, `EXTRACT_DAILY_ENABLED`, `DIGEST_ENABLED`, each set to `true` when you want that part on. `docs/digest.md` has a safe order for turning the email on: dry run, one real send by hand, then the variable.

The pipeline code is Apache-2.0 (see `LICENSE` and `NOTICE`).

## When something breaks

There's no alert system. A failed run shows as a red X in the Actions tab, and nobody is emailed except through GitHub's own notification settings for the repo, so turn those on for whoever's responsible.

* **Collection fails.** The usual cause is SAM.gov changing something: it uses undocumented web endpoints for attachment lists, downloads and award blocks. Read the failed step's log.
* **No email one day.** Check the digest run's log and its `digest` artifact. Only one email goes out per Eastern-time day, even if the job runs twice ([docs/digest.md](docs/digest.md)).
* **Email sent but the archive site is stale.** The send itself succeeded. Run "Deploy digest web archive" by hand. If saving the archive entry failed, `docs/digest.md` explains how to add it by hand.
* **The email didn't go out at all.** Check the `BUTTONDOWN_API_KEY` secret and the `DIGEST_ENABLED` variable first. To start the email's memory over, delete `analysis/digest_state.json` from the dataset (the next run then covers the last 36 hours).
* **A day is missing from collection.** Rerun "Daily J&A collection" from the Actions tab.

## Running it yourself

PDF text is read with `pdftotext` from poppler (`brew install poppler`, or `apt-get install poppler-utils`). Without it the code falls back to `pypdf`, which splits a few words and drops some apostrophes, so install it. `daily.yml` and `tests.yml` install it on the runner. Set `JA_PDF_ENGINE=pypdf` to force the old reader. Each page row says which one read it (`pages.text_engine`).

```sh
uv sync --frozen
uv run pytest -q                      # the full test suite, no network, no API calls
uv run ja-collect --help              # the collection commands
uv run python -m federal_ja.analysis digest --dry-run --out work/digest   # builds an email, sends nothing
```

All 406 tests passed on 2026-11-05 on this branch, including with `JA_GITHUB_REPO`, `JA_HF_REPO` and `JA_BUTTONDOWN_USER` changed. A real run needs `HF_TOKEN` and `ANTHROPIC_API_KEY` in your environment (a `.env` file works; it's gitignored).

## Known limits

* The `analysis/` tables are AI-generated and the dataset card says so. Don't remove that label.
* The theme tables (`experimental_theme_tags`, `experimental_theme_status`) are a one-off snapshot and don't update.
* SAM.gov's endpoints are undocumented and can change without notice.
* Pages published before 2026-11-06 were read with `pypdf` and keep that text. Only new documents are read with `pdftotext`; `pages.text_engine` tells the two apart. `ja-collect reread_text` can re-read the old ones (`ja-collect --workdir work pull`, then `reread_text --limit 500 --report work/reread.csv`, then `publish`), but don't run it on its own: in a sample, about 9% of the existing extraction quotes stopped matching the re-read text (the quote had copied a `pypdf` split word, or the block moved). Re-read and re-extract together, and expect an Anthropic bill for the re-extraction.
